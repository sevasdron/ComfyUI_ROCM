# Обновление ComfyUI

Требование: переходить на свежий ComfyUI быстро, без риска для рабочей сборки
и с откатом за минуту.

## Темп upstream

С 13.08 по 10.09.2026 вышло 14 релизов, с v0.33.0 до v0.35.1 — в среднем раз в 2 дня.
Между 0.31.0 (наша версия) и 0.35.1 — 195 коммитов. В master после 0.35.1 ещё 28.

Что меняется от релиза к релизу (на примере 0.31.0 → 0.35.1, `requirements.txt`):

| Пакет | 0.31.0 | 0.35.1 |
|---|---|---|
| comfyui-frontend-package | 1.48.7 | 1.51.10 |
| comfyui-workflow-templates | 0.11.34 | 0.11.59 |
| comfyui-embedded-docs | 0.5.9 | 0.5.11 |
| comfy-kitchen | 0.2.28 | 0.2.33 |
| comfy-aimdo | 0.4.13 | 0.5.3 |
| av | >=16.0.0 | >=17.0.0 |

torch в requirements не закреплён, поэтому обновление ядра не требует менять runtime.
Это и делает быстрые обновления возможными.

## Каналы

| Канал | Что | Порт | Для чего |
|---|---|---|---|
| `stable` | проверенный тег | 8000 | ежедневная работа |
| `candidate` | последний релизный тег | 8100 | проверка перед переходом |
| `nightly` | master | 8200 | по запросу: попробовать свежий фикс или модель в день выхода |

Каналы — это теги образов модпака, а не отдельные установки.

## Процедура

```
tools/comfy update main --to latest        # или --to v0.35.1 / --to master
```

1. **Выбор версии.** `git ls-remote --tags` ComfyUI, берём нужный тег.
2. **Сборка ядра** `comfy-core:<тег>`. Патчи ядра проверяются `git apply --check`:
   - применился — всё штатно;
   - уже есть в upstream (`git apply --reverse --check` проходит) — патч помечается устаревшим;
   - конфликт — сборка останавливается, нужна ручная адаптация.
3. **Сборка модпака** на новом ядре → тег `candidate`.
4. **Автопроверки** (раздел ниже). Отчёт: что сломалось, что изменилось.
5. **Ручная проверка** на порту 8100 своими воркфлоу. Тяжёлые прогоны — не параллельно
   с `stable`, память общая.
6. **Promote.** Бэкап `user/` (в первую очередь `comfyui.db`), затем `candidate` → `stable`,
   прежний `stable` → `prev`.
7. **Rollback** — перетег `prev` → `stable` и возврат `user/` из бэкапа.

## Автопроверки

| Проверка | Что ловит |
|---|---|
| **Smoke** | torch видит GPU; сервер стартует; в логе нет `IMPORT FAILED` и трейсбеков при импорте нод |
| **Схема нод** | `tests/schema`: diff `/object_info` между `stable` и `candidate` — исчезнувшие ноды, удалённые/переставленные входы, смена типов и выходов (ломающие) отдельно от добавленных в конец (безобидные). Снимок снимает `tools/comfy smoke` |
| **Эталонные воркфлоу** | прогон через API коротких воркфлоу из `modpacks/<имя>/workflows/` на фиксированных сидах: успех, время, пик памяти |
| **Frontend** | главная страница и `/api/extensions` отдаются, JS-расширения нод загружаются без ошибок |

Проверка схемы нужна из-за класса ошибок, который мы уже ловили: ComfyUI сопоставляет
значения виджетов **по порядку**, и лишний вход в середине молча сдвигает все значения
в сохранённых воркфлоу (так сломались 25 воркфлоу с LLMTextProcessor).

Эталонные воркфлоу — маленькие: низкое разрешение, мало шагов, по одному на
каждое семейство моделей (MiniMax H3, Krea2/Flux2, LLM-энхансер, апскейл, видео).
Цель — проверить, что путь работает, а не качество картинки.

## Что учесть

- **База `comfyui.db`** мигрируется alembic вперёд при старте новой версии. Старая версия
  может не открыть обновлённую базу — поэтому бэкап `user/` обязателен перед promote,
  а у `candidate` своя копия `user/`, а не общая со `stable`.
- **Frontend отдельно от ядра.** Попробовать новый интерфейс без пересборки можно ключом
  `--front-end-version Comfy-Org/ComfyUI_frontend@<версия>` (есть в 0.35.1). В `stable` не использовать:
  frontend скачивается при старте и не закреплён в образе.
- **Обновление нод — отдельное действие.** `update` меняет только ядро; ноды остаются на своих
  коммитах из `nodes.lock`. Если новое ядро ломает ноду — чиним в форке или остаёмся на старом ядре.
  Так всегда понятно, что именно сломало сборку.
- **Manager** (`comfyui_manager`) закреплён в `manager_requirements.txt` ядра и обновляется вместе с ним.
- **Патчи ядра — долг.** Каждый патч в `core/patches` замедляет обновления. Всё, что можно,
  отправляем в upstream или выносим в ноду. Пример: исправление GrowMask в 0.35.1 всё ещё не принято
  (`nodes_mask.py:376`, `m.numpy()`).
- **Обновление runtime (torch/ROCm)** — отдельная процедура по тем же шагам, но реже и с полным
  прогоном эталонов: там меняется производительность и стабильность ядер HIP.
