# ADR-0002. Модпаки с закреплёнными нодами и своими форками

Статус: **предложено** · 14.09.2026

## Контекст

Все ноды лежат в одной папке и ставятся в один venv через Manager. Результат:
- второй пакет с тем же идентификатором класса молча перекрыл исходную ноду и сдвинул входы в 25 воркфлоу;
- `Update All` и «Try fix» возвращают сломанные зависимости (pedalboard → SIGILL);
- наши правки в нодах теряются при обновлении, у 18 нод нет даже git.

## Решение

- Модпак — каталог `modpacks/<имя>/` с `modpack.yaml` (базовое ядро, ключи запуска, порт,
  исключения pip) и `nodes.lock` (репозиторий, коммит, патчи для каждой ноды).
- Код нод живёт на хосте в `~/ComfyUI/<имя>/custom_nodes` и монтируется в контейнер;
  в образ модпака входят только их зависимости. `tools/comfy sync` сверяет папку с `nodes.lock`.
- Ноды, которые мы правим, — форки: `origin` — наш форк, `upstream` — оригинал, обновление через rebase.
- Нода с изменённым поведением или входами получает собственный идентификатор класса (префикс `ND_`).
- Manager в модпаках выключен; эксперименты — в отдельной песочнице.
- Обновление нод и обновление ядра — разные действия.

## Последствия

- Состав окружения читается из репозитория и воспроизводится.
- Установка «попробовать новую ноду» становится дольше: песочница → `nodes.lock` → пересборка.
- Воркфлоу, использующие переименованные `ND_`-ноды, несовместимы с чужими сборками — это осознанная цена.
