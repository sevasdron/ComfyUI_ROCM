# ADR-0006. Модпак `main` начинается пустым, ноды добавляются по потребности

Статус: **принято** · 15.09.2026

## Контекст

В старом toolbox 42 каталога нод (6.1 ГБ): 18 без git, у пяти локальные правки, часть ставилась
«попробовать» и в рабочих воркфлоу не участвует. Перенести всё разом в `nodes.lock` значит
сначала восстановить происхождение 18 каталогов, собрать форки P3/P4/P5 и проверить 42 набора
зависимостей на новом ядре — до того, как хоть один воркфлоу заработает в `main`.

## Решение

- `main` стартует с одним пакетом — `comfyui-rocm-halo` (собственные ноды, локальный git).
- Нода попадает в `main`, когда она нужна конкретному воркфлоу: `tools/comfy node add main URL`,
  затем `build main`. Старые каталоги — только справочник ([nodes-inventory.md](../nodes-inventory.md):
  репозиторий, версия, правки).
- Форки с правками (P3, P4, P5) делаются в момент добавления соответствующей ноды.
- Manager в `main` на время набора включён: им удобно смотреть и пробовать; всё поставленное
  мимо `nodes.lock` `tools/comfy sync` показывает как лишнее, и оно либо оформляется через
  `node add`, либо удаляется. Когда состав устоится — `manager: false`.

## Последствия

- Старые воркфлоу открываются в `main` с «missing nodes», пока их ноды не добавлены;
  старый toolbox `strix-halo-comfyui` остаётся резервом на это время.
- Состав `main` отражает реально используемое, а не историю экспериментов.
