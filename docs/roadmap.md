# План работ

Текущий контейнер `strix-halo-comfyui` не трогаем, пока модпак `main` не пройдёт проверки.

## Направления работ (решение пользователя, 18.09.2026)

Углубляться в отдельные воркфлоу заканчиваем: работаем над паком и образом, воркфлоу — способ проверки.
Три направления, ранее запланированное разложено по ним; история этапов — ниже.

### 1. Музыкальное рабочее пространство

**Цель:** максимально удобное место для генерации музыки человеку, который не знает нот и терминологии — и
которое позволяет ему понемногу разобраться и научиться.

| Что | Состояние | Следующий шаг |
|---|---|---|
| Генератор стиля и текста под выбранную модель (наша группа нод «усилитель промпта») | системные промпты написаны: `ACE Step 1.5 Music.txt`, `YuE2 Music.txt`; для MiniMax Music 3 есть авторский `MM Music.txt`. Ни один не подключён | выбор модели → свой системный промпт → разбор ответа по секциям `###` в поля нужной ноды (для ACE ещё bpm/тональность/размер/язык). Разбор — кандидат в ноду пака (п. 2) |
| Референс-трек → описание стиля, темпа, тембра, инструментов, строя — словами, из которых собирается запрос | только идея; в ядре v0.36.0 есть `SheetSage2AudioToABC` (запись → партитура: темп, тональность, аккорды, мелодия) | выбрать средства разбора: SheetSage2 (нужно ядро v0.36.0 и `sheetsage2_bf16`), темп/тональность сигнальными методами, описание тембра и жанра LLM с аудио-входом; что из этого работает на ROCm — проверять |
| Референс как условие генерации (тот же стиль / темп / тембр / замиксовать) | идея 17.09; у `TextEncodeAceStepAudio1.5` есть `generate_audio_codes`, у YuE2 — кавер через партитуру (`cot=melody`), аудио-референса у YuE2 нет | после разбора референса; пункты выбора обсудить отдельно |
| Свой темп и правка мелодии | ✅ `Audio/RH_YuE2_BPM_Score_Editor` (Piano Roll), работает | встроить в общее пространство |
| Обратный перевод итогового промпта на русский | идея | нода пака (п. 2) |
| Обучающая сторона: подписи по-русски, пояснения терминов рядом с полями, «что изменится, если…» | нет | заметки и подсказки в воркфлоу; словарь терминов (BPM, тональность, размер, секции песни) |
| Страховка пустого ответа LLM | нода `RH Text Fallback` написана, не встроена | встроить средствами фронтенда (файлом теряет входы) |

## Идеи на будущее

- **Нода обратного перевода промпта.** Усилитель промпта работает на английском, и итоговый текст, который
  реально уходит в генерацию, пользователь не читает. Нужна нода пака ROCm Halo, которая переводит финальный
  промпт обратно на русский и показывает его рядом с оригиналом — чтобы видеть, что модель поняла и дописала,
  до запуска долгой генерации. Кандидаты на движок перевода: та же локальная LLM вторым вызовом либо
  `comfyui-googletrans` из справочника нод.
- **Prompt Enhancer под ACE Step.** Системный промпт написан 17.09 (`modpacks/main/prompts/ACE Step 1.5 Music.txt`), осталось подключить в воркфлоу и разрезать ответ на поля. Готовый `MM Music.txt` не подходит — он под MiniMax Music 3 и выдаёт
  структурированный caption, а не теги. У аудио-воркфлоу теги стиля и текст песни набираются руками. Усилитель
  промпта у нас уже есть (`LLMTextProcessor` + системные промпты в `/mnt/data/AI_Models/ComfyUI/LLM/prompts/`,
  сейчас 41 файл, под музыку — ни одного). Нужен системный промпт, который учит модель писать под ACE Step:
  теги стиля через запятую (жанр, темп, инструменты, характер вокала, продакшн) и лирику с разметкой
  `[Verse]`, `[Chorus]`, `[Bridge]`, `[Outro]`. Отдельной ноды не требуется — тот же подграф `ND Advanced Prompt`
  с другим файлом системного промпта.
- **Референс-аудио в музыкальных воркфлоу (ACE Step, MiniMax Music).** Загрузка референсного трека с выбором,
  что из него взять: тот же стиль, тот же темп, тот же тембр голоса — либо замиксовать с ним. Пункты выбора
  обсудить отдельно. Техническая опора: у `TextEncodeAceStepAudio1.5` есть флаг `generate_audio_codes`
  («выключить, если даёте аудио-референс»), у ACE-Step 1.5 — режимы по референсу; у MiniMax Music 3 —
  проверить, что принимает нода кодировщика.
- **LLM Text Processor с MTP** ✅ (17.09: форк в паке, P3 перенесён, воркфлоу проверены на сдвиг виджета; прогон с головой — ждёт). Форк `Kvento/ComfyUI-LLM-text-processor_mtp_ND` добавляет спекулятивное декодирование
  (голова-черновик `mtp-*.gguf`, `--spec-type draft-mtp`; наш llama.cpp b10472 режим поддерживает, RADV/Vulkan в образе
  с 17.09). Регистрирует тот же тип `LLMTextProcessor`, то есть заменяет наш пакет целиком; под Linux он тоже не умеет —
  патч P3 переносить руками (код бинарника переехал в nodes.py). Риск: новый виджет `mtp` встаёт вторым после `mmproj`,
  сохранённые воркфлоу (VVJ, Krea, YuE2) проверить на сдвиг значений. Голова для 12B не скачана, есть только для 26B-A4B.
  Нужен для авторского `ND_YuE2_T2M_v1.2.json` (версия с MTP).
- **Страховка пустого промпта.** Нода `RH Text Fallback` написана (ошибка с подсказкой про токены или подстановка
  исходного текста), но в подграф пока не встроена: при вставке файлом фронтенд теряет её входы.
